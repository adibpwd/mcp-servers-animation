# Revisi 04 — Kamera Pan Vertikal: Opsi D Scroll Canvas (17-rest-api)

> Status: **📝 PLAN ONLY, belum dieksekusi.**
> Fitur: canvas total diperpanjang vertikal (5 Act × ~1 layar masing-masing),
> kamera bergerak turun mengikuti cerita via GSAP `cameraY` state.
> Revisi ini independen dari revisi-03 (visual-first) — bisa dieksekusi
> setelah atau bersamaan revisi-03.

---

## 1. Konsep

```
viewport 820×1340 (tetap, tidak berubah)
       ┌──────────────┐  ← y=0
       │   INTRO      │
       │   ACT 1      │  section 0: y 0..1340
       └──────────────┘
       ┌──────────────┐  ← y=1340
       │   ACT 2      │  section 1: y 1340..2680
       └──────────────┘
       ┌──────────────┐  ← y=2680
       │   ACT 3      │  section 2: y 2680..4020
       └──────────────┘
       ┌──────────────┐  ← y=4020
       │   ACT 4      │  section 3: y 4020..5360
       └──────────────┘
       ┌──────────────┐  ← y=5360
       │   ACT 5      │  section 4: y 5360..6700
       └──────────────┘

Total canvas: 820 × 6700
Kamera (translateY) bergerak: 0 → -1340 → -2680 → -4020 → -5360
```

Canvas SVG diperlebar tingginya. Satu `<g id="world">` berisi SEMUA
elemen semua Act sekaligus — posisi sudah di-offset per section.
Kamera = `<g transform="translate(0, {cameraY})">` yang bergerak via
`cameraY` state di-drive GSAP.

Viewport SVG tetap `viewBox="0 0 820 1340"` — export Puppeteer
tidak perlu berubah sama sekali. Yang berubah cuma konten di dalam SVG.

---

## 2. Kenapa Ini Aman untuk Export

Export (`export-lib.js`) menggunakan `tl.totalTime(time)` + `flushSync`
untuk seek setiap frame. Tidak ada yang membaca ukuran DOM atau
screenshot viewport — Puppeteer hanya capture elemen yang tampak di
viewport (820×1340). Karena `cameraY` adalah React state yang di-drive
GSAP timeline yang sama, nilai `cameraY` di setiap `totalTime(t)` akan
deterministik dan konsisten, persis seperti state lain (`pop`, `phaseIdx`,
dll) yang sudah berjalan tanpa masalah.

Tidak perlu perubahan di `export-lib.js`, `PlayerShell.jsx`,
`useTimeline.js`, atau script apapun.

## 3. Implementasi Teknis

### 3.1 State Baru

```jsx
const [cameraY, setCameraY] = useState(0)
```

### 3.2 Konstanta Section Offset

```js
// Tinggi tiap section = VH = 1340
// Offset Y awal tiap section di dalam world canvas
const SECTION_H = VH  // 1340

export const SECTION_OFFSETS = {
  intro: 0,
  act1:  0,        // intro + act1 berbagi section 0
  act2:  1 * SECTION_H,
  act3:  2 * SECTION_H,
  act4:  3 * SECTION_H,
  act5:  4 * SECTION_H,
}
// Total canvas height
export const WORLD_H = 5 * SECTION_H  // 6700
```

Semua posisi elemen per-Act di-offset dengan `SECTION_OFFSETS[actN]`:

```js
// Contoh: BUILDING_POS tetap { x: 366, y: 130 } di dalam section-nya.
// Posisi absolut di world = { x: 366, y: SECTION_OFFSETS.act1 + 130 }
// Tapi karena elemen di-render di dalam <g transform="translate(0, offset)">
// per section, posisi lokal TIDAK berubah — hanya wrapper-nya yang di-offset.
```

### 3.3 Struktur JSX

```jsx
<svg viewBox={`0 0 ${VW} ${VH}`} ...>
  {/* background grid — cukup 1 layer, mengisi viewport saja */}
  <rect ... fill={COLORS.BG} />
  <g opacity={0.05}> {/* grid lines */} </g>

  {/* HEADER — fixed di viewport, tidak ikut scroll */}
  {/* (typing intro + phase badge + caption bar) */}
  {renderHeader()}

  {/* WORLD — semua konten cerita, digeser kamera */}
  <g transform={`translate(0, ${cameraY})`}>

    {/* Section 0: ACT 1 — y offset 0 */}
    <g transform={`translate(44, ${SECTION_OFFSETS.act1 + 220})`}>
      <g transform="translate(0, 80)">
        {/* semua elemen Act 1 persis seperti sekarang */}
        {renderAct1()}
      </g>
    </g>

    {/* Section 1: ACT 2 — y offset 1340 */}
    <g transform={`translate(44, ${SECTION_OFFSETS.act2 + 220})`}>
      <g transform="translate(0, 80)">
        {renderAct2()}
      </g>
    </g>

    {/* Section 2: ACT 3 — y offset 2680 */}
    <g transform={`translate(44, ${SECTION_OFFSETS.act3 + 220})`}>
      <g transform="translate(0, 80)">
        {renderAct3()}
      </g>
    </g>

    {/* Section 3: ACT 4 — y offset 4020 */}
    <g transform={`translate(44, ${SECTION_OFFSETS.act4 + 220})`}>
      <g transform="translate(0, 80)">
        {renderAct4()}
      </g>
    </g>

    {/* Section 4: ACT 5 — y offset 5360 */}
    <g transform={`translate(44, ${SECTION_OFFSETS.act5 + 220})`}>
      <g transform="translate(0, 80)">
        {renderAct5()}
      </g>
    </g>

  </g>{/* end WORLD */}

</svg>
```

### 3.4 Header Fixed

Header (intro typing, phase badge, caption bar) **tidak ikut scroll** —
di-render di luar `<g transform={cameraY}>`. Ini penting:
- Saat kamera pan, penonton tetap lihat badge Act dan caption yang update.
- Phase badge dan caption bar tetap di koordinat tetap (y ~155–220).
- Background `<rect fill={COLORS.BG}>` di belakang header perlu di-clip
  atau di-render ulang di atas world agar world yang scroll tidak
  "tembus" ke area header.

```jsx
{/* Header background — di atas world, tidak ikut scroll */}
<rect x={0} y={0} width={VW} height={220} fill={COLORS.BG} />
{renderHeader()}
```

### 3.5 Kondisi Render per Section

Sekarang `{phaseIdx === N && (...)}` dipakai untuk hide/show section.
Dengan opsi D, **semua section selalu di-render** (tidak conditional per
phaseIdx) — mereka hanya tidak terlihat karena di luar viewport.

Ini berarti:
- `phaseIdx` state masih dipakai untuk badge/caption (header).
- Kondisi `{phaseIdx === N && ...}` di JSX **dihapus** — semua Act
  selalu mounted.
- Pop state tiap elemen masih dipakai untuk animasi masuk/keluar lokal.
- Elemen yang "belum giliran" tidak masalah ter-render karena
  `opacity={O('id')}` defaultnya 0 (scale 0).

### 3.6 GSAP Camera Pan

Di dalam `useEffect` master timeline, tambahkan kamera pan di antara Act:

```js
// Helper kamera pan
const panTo = (tl, time, targetY, duration = 0.9, ease = 'power2.inOut') => {
  const cam = { y: cameraYRef.current }
  tl.to(cam, {
    y: targetY,
    duration,
    ease,
    onUpdate: () => {
      cameraYRef.current = cam.y
      setCameraY(cam.y)
    },
  }, time)
}

// Ref untuk nilai kamera saat ini (untuk interpolasi)
const cameraYRef = useRef(0)
```

Pan dipanggil di akhir tiap Act, sebelum Act berikutnya mulai:

```js
// Akhir Act 1 → pan ke Act 2
panTo(tl, act1End - 0.5, -SECTION_OFFSETS.act2, 0.9)

// Akhir Act 2 → pan ke Act 3
panTo(tl, act2End - 0.5, -SECTION_OFFSETS.act3, 0.9)

// dst.
```

Durasi pan 0.9s — overlap 0.5s dengan akhir Act sebelumnya supaya
transisi terasa smooth (kamera mulai gerak saat elemen terakhir Act masih
visible, bukan setelah layar kosong).

**Ease yang dipakai:** `power2.inOut` — acceleration awal + deceleration
akhir, memberikan kesan "kamera film" bukan "scroll web".

## 4. Elemen yang Perlu Dipikirkan Ulang

### 4.1 Gedung & CustomerCharacter (Anchor Persisten)

Di revisi-02, gedung dan pelanggan adalah anchor "persisten" yang muncul
sekali di Act 1 dan tidak di-reset sampai akhir. Dengan opsi D (semua
Act terpisah di section masing-masing), ada dua pilihan:

**Pilihan A (direkomendasikan): Gedung & pelanggan muncul ulang di tiap
section yang relevan.**
- Setiap section punya instance sendiri.
- Lebih mudah implementasinya, posisi sudah relative per section.
- Trade-off: continuity visual "karakter berjalan dari atas ke bawah"
  tidak ada.

**Pilihan B: Gedung & pelanggan ikut scroll bersama world.**
- 1 instance saja, posisinya di section Act 1.
- Saat kamera pan ke Act 2, gedung & pelanggan ikut "naik" keluar viewport.
- Kecuali gedung mau di-"re-enter" di Act 2 dengan posisi yang sudah
  di-adjust. Terlalu rumit untuk sekarang.

**Keputusan: Pilihan A.** Tiap section punya gedung & pelanggan sendiri
yang muncul fresh saat section masuk viewport. Ini lebih maintainable
dan lebih mudah dikombinasikan dengan revisi-03 (visual-first).

### 4.2 `flyEnv` / `flyLock` (Elemen Terbang)

Elemen terbang (`flyEnv`, `flyLock`) pakai koordinat absolut yang
di-lerp. Dengan opsi D, koordinat terbang harus relatif ke section-nya
(sudah di-offset). Karena elemen terbang di-render di dalam `<g
transform="translate(44, OFFSET+220)">`, koordinat lokal tidak perubah
— `ENVELOPE_REST_POS`, `SECRET_ENVELOPE_START`, dst tetap pakai
koordinat lokal per section.

### 4.3 Phase Badge & Caption Bar

Tetap di header fixed (tidak scroll). `phaseIdx` state dipertahankan
untuk update badge/caption saat kamera pan mulai. Timing update `setPhaseIdx`
bisa disejajarkan dengan `panTo` agar badge ganti saat kamera mulai gerak:

```js
// Saat pan ke Act 2 mulai:
tl.add(() => setPhaseIdx(1), act1End - 0.5)
panTo(tl, act1End - 0.5, -SECTION_OFFSETS.act2)
```

### 4.4 Background Grid

Grid sekarang ada di belakang semua konten. Dengan world canvas yang
panjang, grid perlu di-render **di dalam world** (ikut scroll) supaya
terisi di semua section, ATAU cukup tetap di viewport (tidak scroll) —
keduanya ok karena grid hanya dekorasi. Lebih mudah: biarkan grid di
viewport (tidak scroll), penonton tidak akan sadar perbedaannya.
