## 🔍 Diagnosis — 4 Masalah Konkret

### Masalah 1 — Muka (face/people) di browser & server harus dihapus

**Browser (`BrowserWindow`):** Ada 3 elemen muka inline SVG:
```jsx
<circle cx={-20} cy={20} r={3.5} fill={COLORS.TEXT} />   // mata kiri
<circle cx={20}  cy={20} r={3.5} fill={COLORS.TEXT} />   // mata kanan
<path d="M -18 42 Q 0 32 18 42" ... />                   // mulut
```
Hapus ketiga baris ini.

**Server (Officer):** Komponen `Officer` (anchor `'officer'`) punya 3
icon PNG (neutral/thinking/happy). Ini yang dimaksud "people di web
server". Tapi `Officer` terlibat di Act 3 timeline:
- `setOfficerThinking(true)` + `ThoughtBubble` → beat mikir
- `setOfficerHappy(true)` + `foundCheck` → beat data ketemu

Kalau officer dihapus, beat-beat ini kehilangan focal point visualnya.
**Solusi:** Hapus render `Officer` component & anchor-nya, tapi
pertahankan `ThoughtBubble` (nempel di server building) dan
`foundCheck` (badge notif tetap ada, tapi garis konektornya dihapus
karena tidak ada lagi officer yang dituju). State `officerThinking` /
`officerHappy` tetap ada di timeline tapi tidak dirender — tidak perlu
dihapus dari state/timeline, cukup hapus JSX render-nya.

### Masalah 2 — "Kotak" di web server yang mengaburkan bentuknya

**Root cause:** `ServerBuilding` component render kotak pintu SVG
di atas icon `server-building` PNG:
```jsx
<g transform={`rotate(${open ? -55 : 0}, -22, 40)`}>
  <rect x={-22} y={-40} width={44} height={80}
    fill={COLORS.SERVER_DIM} stroke={COLORS.SERVER}
    strokeWidth={2} opacity={0.85} />
</g>
<circle cx={16} cy={40} r={3} fill={COLORS.SERVER} opacity={open ? 0 : 1} />
```
Rect orange besar ini menutupi sebagian icon server building, dan pas
`open=false` terlihat sebagai "kotak asing" yang tidak jelas bentuknya.

**Solusi:** Hapus seluruh blok `<g rotate>` (rect pintu) dan circle
doorknob. Icon `server-building` PNG dibiarkan tampil bersih tanpa
overlay apapun. `server-active` overlay tetap dipertahankan (itu hanya
muncul saat `serverActiveShown` dan lebih subtle — icon glow, bukan rect).

### Masalah 3 — Amplop biru di belakang server (reqEnvelope)

"Surat biru di belakang web server" = amplop request (`reqEnvelope`
warna `COLORS.CLIENT` biru) yang posisinya terbang ke server dan
berhenti di y≈850 (posisi server). Di Act 3 dan seterusnya amplop ini
masih terlihat karena tidak pernah di-popOut setelah "masuk server".

Konfirmasi dari kode: `reqEnvelope` di-popIn Act 1 beat Nulis Surat,
terbang ke DNS (fly1) lalu ke server (fly2). Setelah `doorOpen=true`
(t+5.6 Act 2), amplop berhenti di y=850 dan **tidak ada popOut**
sampai akhir Act. Jadi dia kelihatan terus nangkring di belakang
server building selama Act 3 dan 4.

**Solusi:** Tambah `popOut(tl, t+5.8, 'reqEnvelope', {duration:0.4})`
di Act 2 setelah amplop "masuk pintu" (doorOpen t+5.6) — kesan amplop
sudah masuk ke dalam gedung, bukan nempel di luar.

### Masalah 4 — Stamp 200/404/500 perlu dirapatkan + ikut terbang ke browser

**Sub-masalah 4a — posisi stamp terlalu berjauhan:**
Sekarang: `stampMain (410,935)`, `stampVariant0 (250,1010)`,
`stampVariant1 (570,1010)` — jarak horizontal 160px dan vertikal 75px.
Di canvas 820px portrait ini terasa terlalu tersebar.

Usulan: rapatkan ke cluster lebih kompak:
- `stampMain` tetap di (410, 935) — anchor utama tidak berubah
- `stampVariant0`: (310, 1000) — dari 250→310 (lebih dekat ke center)
- `stampVariant1`: (510, 1000) — dari 570→510 (lebih dekat ke center)

**Sub-masalah 4b — stamp ikut terbang ke browser:**
Sekarang di Act 3 (lanjutan), amplop response tersegel (`replyEnvelopeSealed=true`)
di t+5.4 dan terbang ke browser `fly3` di t+5.6. Stamp tidak ikut —
dia tetap di posisi lamanya (410,935) walau amplop sudah terbang.
Secara naratif ini benar (`stampMain` = tanda di amplop, harusnya
ikut), tapi visualnya stamp dan amplop jadi "berpisah".

**Solusi:** Tween `stampMain` mengikuti `fly3` (mirroring tween yang
sama), begitu pula stamp variant. Atau opsi yang lebih simpel: **popOut
stamp sebelum amplop terbang** (t+5.3 → popOut stamp di t+5.2,
amplop terbang t+5.6 — kesan stamp sudah "menyatu" ke amplop sebelum
terbang). Lebih simpel dan tidak perlu state position baru.

Rekomendasi: **popOut stamp dulu, lalu terbang amplop** — cleanest
secara visual dan paling sedikit kode. Kalau user mau stamp ikut
terbang sungguhan bisa jadi revisi terpisah.

### B — Hapus Officer render (JSX block `T('officer', ...)`)

```jsx

  </g>
```

State dan timeline tidak disentuh.

### C — Hapus kotak pintu di `ServerBuilding`

Sisakan hanya `<image server-building>` + `<image server-active>`.

### D — popOut reqEnvelope setelah masuk server (Act 2 timeline)

```js

```

### E — Rapatkan posisi stampVariant0/1
- `stampVariant0`: (250,1010) → (310,1010)
- `stampVariant1`: (570,1010) → (510,1010)

### F — PopOut stamp sebelum amplop terbang (Act 3 timeline)
Sekarang `replyEnvelopeSealed=true` di t+5.4, amplop terbang t+5.6.
Tambah popOut ketiga stamp sebelum amplop terbang:
```js

popOut(tl, t + 5.2, 'stampVariant0', { duration: 0.3 })
popOut(tl, t + 5.2, 'stampVariant1', { duration: 0.3 })
```
Urutan: stamp fade → amplop tersegel (t+5.4) → amplop terbang (t+5.6).
