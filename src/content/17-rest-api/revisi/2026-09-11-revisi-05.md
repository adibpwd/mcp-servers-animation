# Revisi-05: Profil Visual Adib, API Service Terpadu, dan Ritme Lebih Cepat

**Tanggal:** 2026-09-11
**Status:** Rencana saja — belum ada perubahan kode, aset, atau timeline.

## 1. Tujuan Revisi

1. Method REST harus menunjukkan benda/data yang nyata, bukan teks atau JSON.
2. Browser → API dibuat lebih cepat; pengolahan di server dibuat lebih lama dan jelas.
3. Endpoint dan server disatukan secara visual sebagai satu **API Service**.
4. Pembukaan dimulai dari browser yang berisi user, bukan kotak generik.
5. Asset baru harus berupa icon flat yang jelas, maksimal empat warna aksen.

## 2. Cerita dan Data Visual

Gunakan satu profil visual bernama **Adib**: usia **26**, memakai jas,
rambut **hitam**, dan role **Student**. Browser menampilkan Adib dan
meminta profilnya melalui tiket kecil `GET /users/adib`.

Data tidak pernah berupa JSON. Data berbentuk **kartu profil** dengan avatar
berjas serta tiga piktogram: kalender + `26`, topi wisuda/briefcase untuk
role, dan rambut avatar sebagai atribut yang berubah.

```text
Browser Adib ── tiket GET ──► ┌──────── API SERVICE ────────┐
                             │ endpoint gate → processor    │
                             │              → user cabinet  │
                             └──────────────────────────────┘
```

Endpoint gate adalah pintu routing singkat di dalam panel yang sama dengan
processor dan lemari kartu. Bukan dua gedung atau dua kotak terpisah.

## 3. Arti Visual Tiap Method

| Method | Objek | Aksi visual | Arti |
|---|---|---|---|
| GET | Kartu Adib: 26, Student, rambut hitam | Kartu keluar dari lemari dan masuk ke browser | Mengambil resource yang sudah ada |
| POST | Kartu baru bernama Nina | Kartu baru masuk ke slot kosong dengan tanda plus dan status 201 | Membuat resource |
| PUT | Seluruh kartu Adib | Kartu lama dibalik/keluar, lalu kartu versi lengkap baru masuk; rambut hitam menjadi ungu | Mengganti seluruh resource |
| PATCH | Badge role Adib | Hanya badge Student terlepas dan berubah menjadi Worker; avatar dan usia tetap | Mengubah satu field |
| DELETE | Kartu Nina yang dibuat pada POST | Kartu yang sama ditarik ke tray arsip; slot kosong dan status 204 | Menghapus resource |

Dengan urutan ini, perubahan punya sebab-akibat visual: GET mengenalkan data
awal, POST membuat kartu baru, PUT mengganti kartu Adib secara utuh, PATCH
hanya mengubah role, dan DELETE menghapus kartu Nina yang sebelumnya dibuat.

## 4. Pembukaan Baru

Act 1 dimulai dari **icon browser yang sudah berisi profil Adib**, bukan
ClientBox. Adib menekan tombol/icon kecil “lihat profil”; dari titik klik
lahir tiket request berbentuk **kartu akses kecil** berisi mini-avatar dan
label `GET /users/adib`. Tiket itulah yang bergerak ke API Service.

Browser harus terlihat seperti halaman profil ringan—ada avatar dan satu-dua
baris UI—bukan frame kosong atau kotak label.

## 5. Tempo dan Tata Letak

Target durasi: **46 detik**, dari 54 detik saat ini. Pengurangan hanya pada
perjalanan dan hold kosong; perubahan kartu di server tetap cukup lama untuk
dibaca.

| Act | Target | Fokus |
|---|---:|---|
| 1 — Adib meminta profil | 8s | Browser/avatar muncul, tombol diklik, tiket GET lahir |
| 2 — Tiket masuk API Service | 5s | Perjalanan cepat; endpoint hanya routing singkat |
| 3 — API mengolah kartu Adib | 15s | Lemari buka, kartu dipilih, atribut terlihat, response dibungkus |
| 4 — Profil kembali ke browser | 7s | Kartu kembali cepat dan tampil sebagai profil |
| 5 — Method mengubah koleksi | 11s | POST, PUT, PATCH, DELETE mengubah kartu nyata |
| **Total** | **46s** | Perjalanan cepat, pengolahan data terbaca |

Aturan gerak:

- Tiket browser → API Service: sekitar **1,2–1,5 detik**.
- Endpoint menerima dan meneruskan tiket: maksimum **0,8 detik**.
- Tidak ada hold setelah routing; perhatian langsung pindah ke processor dan lemari.
- Flip PUT, pergantian role PATCH, serta masuk/keluar kartu diberi **1,2–1,8 detik** agar jelas.

## 6. Asset Plan — `icons.json` Baru

Buat `src/content/17-rest-api/icons/icons.json`, kemudian generate PNG
transparan bergaya **flat SVG** (outline tebal, siluet jelas, detail minimum).
Gambar dipakai untuk bentuk/karakter; teks dinamis seperti `26`, `Student`,
`Worker`, method, dan status tetap dirender di SVG/JSX.

### Palet: maksimal 4 warna aksen

| Warna | Fungsi |
|---|---|
| Sky `#38BDF8` | Browser, request, client |
| Violet `#A78BFA` | Rambut ungu / profil versi baru |
| Amber `#FBBF24` | API Service, processor, highlight aksi |
| Green `#34D399` | Sukses dan status response |

Outline gelap/putih hanya neutral untuk keterbacaan, bukan aksen tambahan.
Tanpa gradient dan tanpa warna acak.

| No. | ID | Wujud yang wajib terbaca |
|---:|---|---|
| 1 | `browser-adib-profile` | Browser dengan avatar Adib dan mini layout profil, bukan browser kosong |

### Batch-2 — Operasi Kartu (2 × 4; dua slot kosong)

| No. | ID | Wujud yang wajib terbaca |
|---:|---|---|
| 1 | `profile-request-ticket` | Tiket akses dengan mini-avatar dan garis motion, bukan amplop/kotak kosong |
| 2 | `add-card-plus` | Kartu masuk dengan simbol plus untuk POST |
| 3 | `replace-card-flip` | Dua kartu bertumpuk dengan panah flip/replace untuk PUT penuh |

`adib-purple-hair` wajib memiliki pose, framing, jas, dan proporsi yang
identik. Hanya warna rambut yang berubah, supaya PUT langsung terbaca.

## 8. Kriteria Penerimaan

- Tanpa JSON, penonton tahu GET mengambil profil Adib berusia 26.
- PUT terbaca sebagai ganti kartu penuh dengan rambut hitam → ungu.
- PATCH terbaca sebagai perubahan satu field: Student → Worker.
- POST dan DELETE jelas mengoperasikan kartu Nina yang sama.
- Browser → API Service cepat, sedangkan pengolahan kartu menjadi fokus utama.
- Endpoint dan server terbaca sebagai satu API Service, bukan dua tempat terpisah.
