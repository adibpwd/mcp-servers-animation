## Tujuan Video yang Dikunci

Setelah menonton, audiens memahami tiga hal:

1. **Nginx dan Apache adalah contoh web server**: process yang mendengarkan request HTTP/HTTPS pada server.
2. **File statis** adalah file yang sudah tersedia di disk, misalnya HTML, CSS, JavaScript, gambar, atau PDF. Web server dapat membaca lalu mengirim file itu langsung sebagai response.
3. **Aplikasi upstream** adalah process aplikasi terpisah di belakang web server, misalnya aplikasi Node.js, Python, PHP-FPM, atau Java. Saat request membutuhkan data/logic dinamis, web server meneruskan request kepadanya; aplikasi membuat response lalu mengembalikannya melalui web server.

Scope video bukan membandingkan konfigurasi atau performa Nginx versus Apache. Keduanya tampil sebagai contoh yang setara pada peran “web server listener”; perbedaan produk hanya ditegaskan secara aman: konfigurasi dan fitur dapat berbeda.

## Perbaikan Model Mental

```text
Browser meminta /about
  → Nginx atau Apache menerima di HTTP/HTTPS listener
  → file about.html sudah ada di disk
  → web server membaca file
  → browser menerima halaman

Browser meminta /api/profile
  → Nginx atau Apache menerima di HTTP/HTTPS listener
  → request perlu data/logic dinamis
  → web server meneruskan request ke app upstream
  → app membuat JSON response
  → web server mengembalikan response ke browser
```

**Definisi visual yang wajib:**

| Istilah | Bentuk visual | Bukti yang harus tampak |
|---|---|---|
| Web server listener | Process card bertuliskan `Nginx` atau `Apache`, dengan socket/ring `HTTP/HTTPS` | Packet hanya diterima ketika masuk ke ring listener. |
| File statis | Rak/disk file dengan tile `about.html`, `style.css`, atau gambar | Tile sudah ada sebelum request; satu tile bergerak/di-copy menjadi response. |
| App upstream | Process card terpisah bertuliskan `App` dengan contoh kecil `Node.js` atau `Python` | Process baru aktif setelah forwarded packet tiba; ia membuat JSON/body, bukan mengambil file tile. |
| Response | Capsule/body yang berasal dari file tile atau app output | Capsule kembali ke browser melalui web server, bukan muncul langsung di browser. |

## State Contract yang Direvisi

| State | Yang terlihat | Yang belum boleh terlihat | Pemicu | Hasil |
|---|---|---|---|---|
| Awal | Browser, listener Nginx/Apache redup, static files dan app upstream terlihat redup | Halaman/JSON response | Browser membuka URL | Request packet lahir |
| Listener menerima | Packet masuk ring HTTP/HTTPS pada Nginx/Apache | Jalur static/dynamic terpilih | Listener membaca path | Path chip memberi keputusan jenis resource |
| Static dipilih | File tile sudah ada; app tetap redup | JSON dari app | Path `/about` cocok file | Tile disalin menjadi HTML response |
| Dynamic dipilih | App upstream masih idle; file static tidak berubah | JSON response | Path `/api/profile` diteruskan | App menerima packet dan membentuk JSON response |
| Browser selesai | Response kembali lewat listener | Klaim app sehat tanpa response valid | Body tiba di browser | Browser merender halaman atau data profile |

## Storyboard Pengganti

| Act | Action id | Before → intent → travel → apply → after | Hold |
|---|---|---|---:|
| 1. Siapa yang menerima? | `request-ke-listener` | Browser belum terhubung → URL dibuka → request bergerak ke ring HTTP/HTTPS → packet masuk Nginx/Apache → process listener menyala. | 0,8s |
| 2. Halaman statis | `serve-static-file` | `about.html` sudah ada di file shelf, browser loading → path `/about` dipilih → read pulse dari listener ke tile → tile menjadi response capsule → browser menerima halaman; app upstream tetap idle. | 1,0s |
| 3. Data dinamis | `forward-ke-upstream` | App upstream idle, tidak ada JSON → path `/api/profile` dipilih → forwarded packet dari listener ke app → packet masuk app → app membentuk JSON response; file tile tidak berubah. | 1,0s |
| 4. Response selalu kembali lewat web server | `return-via-web-server` | JSON berada di app upstream → app mengirim response → capsule kembali ke Nginx/Apache → listener mengirim ke browser → browser menampilkan data; dua jalur dibandingkan singkat. | 1,0s |

## Layout dan Asset yang Direvisi

- Letakkan browser di atas, Nginx/Apache listener di tengah, file shelf di kiri bawah, dan app upstream di kanan bawah.
- Kedua jalur harus memiliki akar sama pada listener dan bercabang **setelah** path decision. Static memakai read pulse; dynamic memakai packet forward.
- File tile sudah ada dari awal; JSON response dan active app state baru muncul pada beat apply. Ini membuktikan perbedaan “file tersedia” vs “response dibuat”.
- Jangan hanya memakai label `static` atau `upstream`: tampilkan disk/file tile dan app process yang berbeda bentuk.
- Asset awal tetap inline SVG; tidak ada PNG wajib. Jika logo Nginx/Apache dipakai, ia hanya pendukung identitas dan tidak menggantikan process card/ring listener.
- Bounding box file shelf dan app card harus diaudit saat keduanya tampak pada frame perbandingan. Semua actor tetap dalam safe area `ContentBodyV1`.

## Timeline dan SFX

- Request yang masuk listener menjadi dua handoff berbeda, bukan di-pop-out lalu hasil muncul.
- Static response: read pulse → file tile/response capsule → browser; gunakan SFX ringan `ui`/`success`.
- Dynamic response: forwarded packet → app active → JSON capsule → listener → browser; gunakan `whoosh` saat forward dan `success` saat response terbentuk.
- Reset tiap loop: active route, listener glow, app state, file-read pulse, response capsule, dan browser result.
- SFX dan timing implementasi nantinya wajib masuk schedule export dengan timestamp yang sama.

## Batas Aman

- Tidak ada config block Nginx/Apache, command instalasi, port scan, domain/IP nyata, atau deployment instruction.
- Jangan menyatakan static selalu lebih cepat atau Nginx/Apache selalu dipakai bersama upstream; video hanya menunjukkan dua pola umum.
- Jangan menampilkan output aplikasi sebelum packet benar-benar tiba di app upstream.
