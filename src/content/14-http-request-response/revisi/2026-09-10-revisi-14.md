## 🔍 Diagnosis — 3 Masalah Konkret

### Masalah 1 — Amplop "balik ke browser" di Act 1

**Root cause:** `envelopeAnchor` popIn di `fromY: -300` (muncul dari
atas, turun ke y=700). Lalu di seam Act 1 → "Nulis Surat", amplop
di-crossfade: `envelopeAnchor` fade out, `reqEnvelope` muncul di
(410,700) lalu di-tween naik ke `y: 330` via `morphObj`.

Jadi urutan yang terlihat:
1. Amplop kabur turun dari browser → berhenti y=700 ✅
2. Crossfade: amplop kabur → amplop surat → **naik ke y=330** ← INI yang keliatan "balik ke atas"
3. Act 2: amplop dari y=330 terbang ke DNS (fly1 `y: reqEnvelopePos.y`)

**Kenapa naik?** Posisi "istirahat nulis surat" y=330 dipilih supaya
tidak nimpa NodeLabel browser (y=375, revisi-07 §B). Tapi dari
perspektif penonton, amplop yang sudah "berangkat ke bawah" malah naik
lagi ke dekat browser — KONTRADIKSI naratif.

**Fix:** Hapus `morphObj` tween (amplop naik ke y=330). `reqEnvelope`
langsung muncul dan diam di y=700 (posisi amplop landed). NodeLabel
browser di y=375 memang akan overlap sedikit, tapi itu tidak masalah —
lebih baik sedikit overlap daripada amplop kelihatan "balik ke atas".
`reqEnvelopePos` default state diubah ke `{ x: 410, y: 700 }`.

Konsekuensi ke fly1 (Act 2): `fly1` start dari `reqEnvelopePos.y`
yang sekarang 700 (bukan 330), jadi amplop langsung terbang dari 700
ke DNS. Ini justru lebih natural.

### Masalah 2 — DNS harus tampil sebagai "Gerbang" yang ngatur routing

**User want:** DNS bukan cuma "cari alamat di buku", tapi visual
gerbang/router yang menentukan ke web server mana surat dikirim.
Ada banyak web server potensial, DNS yang ngatur.

**Diagnosis state sekarang:** Act 2 sekarang:
- `addressBook` (buku alamat) popIn bareng amplop terbang ke DNS
- `dnsMagnify` nongol pas scanning (t+1.6)
- `dnsResolvedShown` → `dns-resolved` icon + `RESOLVED_IP` caption
- Langsung ke gedung server satu-satu

**Fix — DNS sebagai gerbang routing:**

Tambah elemen visual baru di DNS zone (y≈620):
1. **"Gerbang" DNS visual**: Pas amplop tiba di DNS, tampilkan icon
   "gateway" atau reuse `dns-resolved` icon dengan cara baru — tampilkan
   beberapa "cabang" kecil keluar dari DNS menuju 2-3 server mini
   (SVG inline, bukan PNG baru). Server mini yang "aktif" (terpilih)
   punya glow/highlight, yang lain dim.
2. **Animasi routing**: Amplop "berhenti" sejenak di DNS (0.5s pause),
   ada visual "DNS memilih jalur", lalu lanjut ke server yang terpilih.

**Implementasi konkret (tanpa icon baru):**
- Di zone DNS (x=610, y=620), setelah `dnsFound=true` (t+3.2 Act 2),
  tambah 3 inline SVG nodes kecil (lingkaran kecil) mewakili
  "kandidat server": kiri (x=500, y=750), tengah (x=610, y=800),
  kanan (x=720, y=750).
- Tween: kandidat server nongol bersamaan, dim semua, lalu satu
  (tengah = server utama kita) highlight/pulse, yang lain fade out.
- Duration total: 0.8s — cukup untuk "keputusan routing" kebaca,
  tidak terlalu lama mengganggu flow.

State baru yang dibutuhkan:
```js
const [dnsGatewayShown, setDnsGatewayShown] = useState(false)
const [dnsRoutingPct, setDnsRoutingPct] = useState(0) // 0-1 animasi pilih jalur
```

### Masalah 3 — Teks isi surat (methodBadge, addressLabel, dll) posisinya salah

**State sekarang:** Semua elemen teks isi surat (methodBadge x=190,
y=330; addressLabel x=410, y=470; domainQuestionBubble x=570, y=950;
hookCliffhangerBadge x=250, y=950; envelopeSealedCard x=410, y=790)
muncul di posisi tetap yang tidak relate ke posisi benang/flowchart
saat itu.

**User want:** Teks muncul **di mana benang sedang berada** — ikut
progress flowchart. Jadi:

| Info | Munculnya di mana | Timing |
|------|-------------------|--------|
| "GET / HTTP" (methodBadge) | Dekat amplop di zona BROWSER (y≈330–400) | Act 1 Nulis Surat t+1.0 |
| Domain address (addressLabel) | Dekat amplop saat Nulis Surat (y≈420) | Act 1 t+1.6 |
| "Domain ≠ IP?" (domainQuestion) | Dekat amplop y≈420 atau inline di benang | Act 1 t+3.5 |
| Amplop tersegel (envelopeSealedCard) | Dekat amplop y≈420 | Act 1 t+5.8 |
| "Isi suratnya apa?" (hookCliffhanger) | Dekat amplop y≈700 (posisi landed) | Act 1 t+5.8 |

**Fix:** Semua teks elemen dipindah agar posisi y mereka mengikuti
posisi amplop saat teks itu muncul, bukan di posisi hardcode yang
tidak berubah.

Prinsip: **teks = badge kecil yang nempel di SAMPING amplop**, bukan
panel terpisah di bawah layar. Posisi x bisa ke kiri atau kanan
amplop (tidak pas di atas icon supaya tidak nutup icon itu sendiri).

Posisi baru:

| Elemen | Posisi lama | Posisi baru | Alasan |
|--------|------------|-------------|--------|
| `methodBadge` | (190, 330) | (190, 420) | Sejajar amplop di y≈420 (setelah morph dihapus, amplop diam di 700 — tapi methodBadge muncul pas amplop baru transisi, sekitar y=700; adjust ke kiri amplop) → **(160, 700)** |
| `addressLabel` | (410, 470) | Di bawah/kiri amplop y=700 → **(410, 790)** | Benang segmen 0→0.33 baru nongol, teks ikut |
| `domainQuestionBubble` | (570, 950) | Di kanan amplop → **(570, 720)** | Masih di zona amplop, bukan jauh di bawah |
| `envelopeSealedCard` | (410, 790) | Dekat amplop yang sudah sealed → **(580, 700)** | Di samping kanan amplop |
| `hookCliffhangerBadge` | (250, 950) | Di kiri amplop → **(240, 700)** | Di samping kiri amplop |

## 📋 Scope Perubahan

### A — Hapus morfObj tween (amplop tidak naik ke y=330)

**File:** `Animation.jsx`

Hapus blok:
```js
const morphObj = { y: 700 }
tl.to(morphObj, {
  y: 330, duration: 0.5, ease: 'power2.inOut',
  onUpdate: () => setReqEnvelopePos({ x: 410, y: morphObj.y }),
}, t + 0.3)
```

Ganti `setReqEnvelopePos({ x: 410, y: 700 })` tetap ada (sudah di
block `tl.add` sebelumnya). Default state `reqEnvelopePos` ubah dari
`{ x: 410, y: 330 }` → `{ x: 410, y: 700 }`.

### B — DNS Gerbang Routing (state + JSX + timeline)

Tambah state:
```js
const [dnsGatewayShown, setDnsGatewayShown] = useState(false)
const [dnsRoutingPct, setDnsRoutingPct] = useState(0)
```

Tambah komponen `DnsGateway` (inline SVG, no new PNG):
```jsx
const DnsGateway = () => {
  // 3 server kandidat: kiri, tengah (terpilih), kanan
  // Kiri & kanan: dim circle + garis putus ke DNS
  // Tengah: pulse circle hijau + garis solid = server yang dipilih
  // dnsRoutingPct 0→1: kandidat fade in (0→0.3), tengah highlight (0.3→0.7), kiri/kanan fadeout (0.7→1.0)
}
```

Di timeline Act 2, setelah `setDnsFound(true)` (t+3.2):
```js
tl.add(() => setDnsGatewayShown(true), t + 3.2)
const routeObj = { v: 0 }
tl.to(routeObj, {
  v: 1, duration: 0.8, ease: 'power1.inOut',
  onUpdate: () => setDnsRoutingPct(routeObj.v),
}, t + 3.2)
tl.add(() => setDnsGatewayShown(false), t + 4.0)
```
Amplop terbang ke server (fly2) mulai t+4.5 — jeda 0.5s setelah
gateway selesai, cukup untuk penonton baca.
