# Revisi-06: Alur Request Tanpa Jeda — GET Selesai di Act 1–2, CRUD Dikirim dari Browser

**Tanggal:** 2026-09-12
**Status:** Rencana sangat detail — belum dieksekusi.

## 1. Keputusan Utama

Revisi ini mengganti struktur lima Act dari Revisi 05 menjadi **empat Act**
yang terus bergerak tanpa beat kosong:

1. **Act 1 — Browser mengirim GET**: request langsung berangkat begitu UI GET
   selesai dibuat.
2. **Act 2 — API mengolah dan mengembalikan GET**: tiket GET tetap terlihat
   masuk ke API Service, kartu Adib diambil, lalu profil kembali ke browser.
3. **Act 3 — Browser mengirim POST dan PUT**: kedua method memakai pola
   request yang sama dari browser ke service, dengan benda/data visual jelas.
4. **Act 4 — Browser mengirim PATCH dan DELETE**: dua operasi terakhir juga
   dikirim dari browser dan mengubah kartu yang sama secara nyata.

**Act 5 dihapus.** Tidak ada galeri method statis setelah GET selesai.
Setiap method adalah request hidup: berangkat dari browser, masuk ke API
Service, mengubah kartu, lalu menghasilkan response/hasil yang terlihat.

Target durasi konten: sekitar **39 detik** (tidak termasuk repeat delay).
Percepatan berasal dari menghapus hold kosong dan meleburkan perpindahan Act,
bukan dari membutakan penonton dengan tween yang terlalu cepat.

## 3. Kontrak Kontinuitas Visual

Aturan ini wajib dipenuhi sebelum pekerjaan dianggap selesai.

### 3.1 API Service sudah hadir sejak Act 1

- Browser tampil di area atas, API Service Hub sudah terlihat **samar** di
  area bawah pada saat yang hampir sama.
- Hub tidak menunggu Act 2/3 untuk muncul. Stroke/label-nya mulai dengan
  opacity sekitar 0,20–0,30 dan naik saat tiket mendekat.
- Di dalam hub, tiga bagian sudah terbaca sebagai satu tempat:
  **Gate → Processor → User Cabinet**.
- Gate dan processor tidak pernah menjadi panel terpisah. Mereka adalah
  compartment di dalam satu panel API Service.

### 3.2 Satu tiket, tidak boleh hilang di tengah jalan

Untuk setiap method, satu tiket request melalui state berikut:

```text
browser UI
  → muncul di titik klik
  → keluar dari browser
  → melaju di spine
  → masuk gate
  → terlihat melintas jalur pendek di dalam hub
  → diserap processor
  → perubahan kartu terjadi
  → response kembali ke browser
```

Larangan:

- Jangan `popOut` tiket di gate lalu baru memunculkan processing beberapa
  detik setelahnya.
- Jangan menyembunyikan hub dan baru menampilkan kabinet saat kartu perlu
  diolah.
- Jangan reset canvas pada pergantian Act.

Transisi yang diizinkan saat tiket masuk processor:

- Skala tiket mengecil maksimal 10–15%, glow menguat, lalu bagian mini-kartu
  di dalamnya diteruskan menjadi kartu yang diolah.
- Durasi ingress maksimal 0,25–0,35 detik.
- Pada frame yang sama atau frame berikutnya, processor menyala dan lemari
  terbuka. Tidak ada frame kosong.

### 3.3 Tidak ada hold yang tidak mempunyai makna

Hold hanya boleh ada untuk:

- membaca detail kartu Adib;
- melihat perubahan penuh PUT;
- melihat perubahan tunggal PATCH;
- mengonfirmasi kartu Nina masuk atau terarsip.

Batas umum:

- sebelum tiket bergerak setelah klik: maksimal **0,25 detik**;
- setelah tiket sampai gate sebelum processor aktif: maksimal **0,35 detik**;
- sesudah response tiba sebelum request berikutnya dibuat: maksimal **0,40 detik**;
- tidak boleh ada badge Act atau caption berdiri sendiri sementara tidak ada
  objek yang berubah.

## 5. Model State dan Objek Persisten

Implementasi nantinya perlu menyimpan state agar setiap perubahan konsisten.

| Objek | State awal | Perubahan | State akhir |
|---|---|---|---|
| Adib | 26, Student, rambut hitam | PUT: rambut ungu; PATCH: Student → Worker | 26, Worker, rambut ungu |
| Nina | Tidak ada; slot lemari kosong | POST menambah Nina; DELETE mengarsipkan Nina yang sama | Tidak ada; slot kembali kosong |
| API Service Hub | Terlihat redup sejak Act 1 | Menyala saat tiap tiket masuk, kabinet buka saat operasi | Redup untuk closing |
| Request ticket | Tidak ada | Satu tiket baru per method, tetapi selalu melaju dari browser hingga processor | Menjadi response/confirmation, tidak teleport |
| Browser | Profil awal/minimal | Menampilkan hasil tiap response dan menyediakan aksi request berikutnya | Profil Adib final |

Reset loop wajib mengembalikan semua state ke awal: Adib rambut hitam,
Student; Nina tidak ada; cabinet slot Nina kosong; hub redup; browser di
halaman awal.

## 6. Intro Morph — Referensi Format Tailscale, Tanpa Typing

Revisi ini mengadopsi struktur intro Tailscale, tetapi menghapus seluruh
typing/cursor/blink. Yang dipertahankan adalah **satu grup teks persisten**
yang di-`lerp` dari hero centered menjadi header kiri-atas.

### Referensi yang dipakai

Tailscale memakai:

- hero text berada di sekitar x = `(VW / 2) - (thumbWidth / 2)`,
  y tagline/title/subtitle = **550 / 640 / 716**;
- target compact header di x = **44**, y = **50 / 100 / 130**;
- ukuran title mengecil **72 → 44** dan subtitle **20 → 15**;
- satu `morphP` ditween selama **0,8 detik** dengan
  `power3.inOut`;
- teks tidak dihapus dan dibuat ulang; posisi dan ukuran yang sama bergerak
  sampai menjadi header.

### Penerapan REST API

| Elemen | Hero awal | Header akhir |
|---|---|---|
| Tagline | `DEVELOPER TOOLS · ADIB-DEV.COM`, x hero, y 550, 18 px | x 44, y 50, 13 px |
| Title | `REST API`, x hero, y 640, 72 px | x 44, y 100, 44 px |
| Subtitle | `Browser → API Service → Profil`, x hero, y 716, 20 px | x 44, y 130, 15 px |

Warna tetap mengikuti palet Revisi 05:

- `REST` sky `#38BDF8`;
- `API` amber `#FBBF24`;
- tagline/subtitle memakai muted neutral;
- tidak ada putih fullscreen, flash putih, atau transisi fade-to-blank.

### Timing intro

| Waktu | Aksi |
|---:|---|
| 0,00 | Title, tagline, dan subtitle lengkap sudah terlihat di tengah; tanpa ketik |
| 0,00–0,20 | Hero diberi settle/pulse sangat halus untuk memberi waktu orientasi |
| 0,20–1,00 | `morphP: 0 → 1`, title group bergerak naik-kiri dan mengecil secara kontinyu |
| 1,00 | Header sudah jadi; phase badge dan browser/hub mulai muncul |
| 1,00–1,20 | Act 1 berjalan; tidak ada layar kosong di antara intro dan konten |

Aturan penting: `showIntro` hanya boleh menyembunyikan phase badge dan
isi cerita sebelum header selesai. Header sendiri tetap hidup setelah
morph; jangan menghitung opacity yang membuat tagline atau judul “putih”
atau menghilang saat `morphP = 1`.

## 8. Kriteria Penerimaan

- GET tidak lagi menunggu di browser setelah tombol diklik.
- API Service sudah tampak dari Act 1; penonton selalu tahu tujuan tiket.
- Tidak ada gap/blank visual ketika GET berpindah dari Gate ke Processor.
- GET selesai sepenuhnya pada akhir Act 2.
- POST, PUT, PATCH, dan DELETE masing-masing berangkat dari UI browser.
- PUT mengganti satu kartu penuh; PATCH hanya mengganti badge role.
- DELETE menghapus Nina yang benar-benar dibuat oleh POST.
- Hanya empat Act yang tersisa, tanpa Act 5/epilog method.
- Intro bergerak dari tengah ke header kiri-atas dengan format Tailscale,
  tanpa typing dan tanpa flash putih/poof.
