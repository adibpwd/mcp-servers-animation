# Revisi-07: Networking Header, Browser Loading, dan Tiga Profil User

Tanggal: 2026-09-12
Status: Rencana detail — belum dieksekusi.

## 1. Keputusan

Revisi ini mempertahankan empat Act dan alur request kontinu dari Revisi 06.

1. Intro memakai mint/hijau dan sky blue seperti Tailscale. Kategori menjadi NETWORKING, bukan Developer Tools.
2. Badge Act dan empat dot kembali memakai pola layout Tailscale.
3. Browser Act 1 hanya memperlihatkan loading profile. Data Adib baru muncul saat response GET kembali.
4. Tiga user dipakai sebagai data visual: Adib, Jokowo, dan Prabowo.
5. Avatar, rambut, seragam sekolah, dan perubahan profesional masuk rencana icon batch baru yang lebih hidup.

Act 5 tetap tidak ada. GET selesai di Act 1–2; POST dan PUT di Act 3; PATCH dan DELETE di Act 4.

## 2. Intro: Networking dan Warna Tailscale

### Kategori dan metadata

Teks kategori intro diubah menjadi:

~~~
NETWORKING · ADIB-DEV.COM
~~~

Nilai rencana yang harus konsisten:

| Lokasi | Nilai |
|---|---|
| data.js, INTRO_CATEGORY | NETWORKING · ADIB-DEV.COM |
| manifest.js, category | Networking |
| scripts/content-db.json | Networking, jika file ini masih metadata pendamping |
| tag | REST, API, HTTP, Networking, Client-Server |

REST API diposisikan sebagai kelanjutan seri networking: browser berkomunikasi dengan API Service melalui request dan response.

### Palet intro

| Elemen | Warna | Fungsi |
|---|---|---|
| REST | Mint green #2CD1A8 | identitas seri networking ala Tailscale |
| API | Sky blue #38BDF8 | komunikasi request-response |
| tagline dan subtitle | muted #94A3B8 | teks pendukung |
| background | navy #070913 | kanvas seri |

Amber hanya dipakai untuk API Service yang sedang memproses. Amber tidak dipakai untuk title intro. Tidak ada flash putih, layar terang, atau fade ke blank.

### Morph tanpa typing

Format meniru struktur Tailscale: satu grup teks lengkap hadir di hero tengah, lalu grup yang sama bergerak dan mengecil ke kiri atas.

| Elemen | Hero | Header akhir |
|---|---|---|
| tagline | x = (VW/2)-210, y 550, 18 px | x 44, y 50, 13 px |
| title REST API | x = (VW/2)-210, y 640, 72 px | x 44, y 100, 44 px |
| subtitle Browser → API Service → Profil | x = (VW/2)-210, y 716, 20 px | x 44, y 130, 15 px |

Timing:

- 0,00–0,20: hero title lengkap settle singkat di tengah.
- 0,20–1,00: satu morph progress 0 ke 1 selama 0,8 detik, ease power3.inOut.
- 1,00: header sudah terbentuk; grup teks tetap hidup dan tidak dibuat ulang.
- 1,00–1,20: badge, browser loading, dan API Service mulai muncul.

Typing, cursor, blink, dan typeLine tidak diperlukan. Yang diadopsi dari Tailscale adalah hero-to-header lerp, koordinat, ukuran, dan kontinuitas grup teks.

## 3. Badge Act, Dot, dan Layout Aman

### Badge mengikuti Tailscale

Badge tidak diletakkan sebagai pill kecil di kanan atas. Format yang dipakai:

~~~
x=44, y=155
┌──────────────────────────── 500 px ───────────────────────────┐   ● ○ ○ ○
│ ●  ACT 1 — ADIB KIRIM GET                                      │
└───────────────────────────────────────────────────────────────┘
                                                                    x=620
~~~

Spesifikasi:

- Badge: x 44, y 155, lebar 500, tinggi 40, radius 20.
- Bullet internal: cx 22, cy 20, memakai warna Act aktif.
- Text: monospace 13 px, bold 700, letter spacing 0,5.
- Dot group: x 620, y 167; jarak antar dot 24 px.
- Ada empat dot, selalu tampil sepanjang video.
- Dot aktif: radius 7, warna Act aktif, stroke putih 1,5 px.
- Dot nonaktif: radius 4, warna BORDER.
- Ketika Act berubah, hanya warna dan radius dot aktif yang berubah.

### Zona vertikal wajib

Browser sekarang dapat menutup subtitle karena terlalu tinggi. Semua posisi baru harus memakai zona berikut.

| Zona | y | Isi |
|---|---:|---|

| Phase navigation | 155–195 | badge dan empat dot |

| Transit zone | 476–590 | ticket request dan spine |
| API Service zone | 610–1.000 | gate, processor, cabinet |

Koordinat rencana:

- center browser utama: y 355; tinggi maksimal 210; panel top minimal y 250;

Tidak boleh memakai nested offset yang membuat browser naik tanpa sadar ke header. Semua objek besar harus dihitung dari konstanta zona.

### Text dan caption

Penjelasan harus menempel pada objek: tombol browser, ticket, card, gate, atau response. Caption global, jika masih dipakai, hanya boleh muncul dekat browser atau API Service; tidak boleh masuk Header atau Phase navigation zone.

## 4. Act 1: Browser Loading Sebelum GET Selesai

Browser awal tidak boleh menampilkan nama Adib, usia, role, rambut, atau avatar final.

Visual browser awal:

~~~
┌──────────────── BROWSER · /profile ─────────────────┐
│                                                      │
│                 ◌  Memuat profil...                  │
│                    GET /users/adib                   │
│                                                      │
│                 [ Lihat Profil ]                     │
└──────────────────────────────────────────────────────┘
~~~

Isi browser:

- avatar placeholder muted atau skeleton neutral;
- spinner mint-sky;
- dua skeleton line;
- tombol Lihat Profil sebagai sebab lahirnya GET.

Urutan:

1. User klik Lihat Profil.
2. Spinner menguat dan text berubah menjadi Mengambil profil.
3. Ticket GET /users/adib lahir dari tombol.
4. Dalam maksimal 0,25 detik ticket langsung bergerak ke API Service.
5. Browser tetap loading saat ticket masuk Gate dan Processor.

Pada return GET 200 di Act 2, baru lakukan:

1. spinner mengecil/fade;
2. skeleton berubah menjadi profile card;
3. avatar Adib muncul;
4. nama, usia, role, dan rambut masuk cepat;
5. aksi POST baru tersedia.

GET akan terbaca sebagai mengambil data yang sebelumnya belum ada di browser.

## 5. Tiga User dan Pembagian Operasi

Avatar harus generik dan tidak menyerupai tokoh publik nyata; nama hanya label contoh.

| User | State awal | Operasi | State akhir |
|---|---|---|---|
| Adib | 12 tahun, Student SD, seragam putih-merah, rambut hitam | GET lalu PUT | Adib 26 tahun, Professional, jas kerja, rambut ungu |
| Jokowo | form browser pendaftaran terpisah, student generik | POST lalu PATCH | dibuat lalu role/outfit berubah Student ke Professional |
| Prabowo | form browser pendaftaran terpisah, member generik | POST lalu DELETE | dibuat lalu kartu yang sama diarsipkan |

Alasan pembagian:

- Adib menjelaskan GET dan PUT penuh.
- Jokowo menjelaskan POST dan PATCH satu field.
- Prabowo menjelaskan POST dan DELETE.
- Ketiganya diproses dalam cerita, bukan hanya dekorasi.

### Dua mini browser untuk POST

Setelah profile Adib selesai dimuat, dua mini browser/form muncul di bawah browser utama:

~~~
[ Browser Adib: profile loaded ]
[ Form Jokowo: + tambah user ]
[ Form Prabowo: + tambah user ]
~~~

Aturan:

- Ukuran maksimum masing-masing 150 × 68 px.
- Muncul stagger 0,15–0,20 detik.
- Tetap berada di Browser zone atau awal Transit zone, tidak boleh lebih tinggi dari y 235.
- Form Jokowo mengirim POST pertama; sesudah 201, form Prabowo mengirim POST kedua.
- Setiap POST adalah request individual ke /users, bukan bulk request.
- Sesudah berhasil, form berubah menjadi mini profile card dengan stempel 201.

## 6. Detail Act 2–4

### Act 2 — GET mengembalikan Adib

- Ticket GET terus terlihat Gate → Processor; tidak pop-out di batas Act.
- Cabinet mengeluarkan card Adib: 12, Student SD, seragam sekolah, rambut hitam.
- Response 200 kembali ke browser.
- Browser loading hydrate menjadi profile Adib.
- Dua mini form Jokowo dan Prabowo muncul pada 0,3–0,5 detik terakhir Act 2 sebagai jembatan menuju Act 3.

### Act 3 — POST Jokowo, POST Prabowo, lalu PUT Adib

Urutan:

1. Form Jokowo mengirim POST dengan mini card Jokowo.
2. API Service memasukkan Jokowo ke slot kosong pertama; response 201 kembali.
3. Maksimal 0,35 detik sesudahnya, form Prabowo mengirim POST kedua.
4. API Service memasukkan Prabowo ke slot kosong kedua; response 201 kembali.
5. Browser Adib masuk mode edit lengkap dan mengirim PUT /users/adib.
6. Card Adib lama keluar sebagai satu card penuh.
7. Card baru masuk penuh: Adib 26, Professional, jas kerja, rambut ungu.
8. Response 200 Replaced kembali ke browser Adib.

Dua POST adalah beat cepat, sekitar 3,2–3,8 detik dari klik sampai confirmation. PUT mendapat hold 1,2–1,6 detik pada pergantian card karena perlu menjelaskan replace penuh.

### Act 4 — PATCH Jokowo lalu DELETE Prabowo

1. Mini card Jokowo menampilkan Student; user klik Ubah role.
2. Ticket PATCH /users/jokowo hanya membawa badge Professional.
3. Card Jokowo tetap di slotnya; layer seragam sekolah/topi berubah menjadi pakaian profesional/briefcase. Nama dan usia tetap.
4. Response 200 Updated kembali.
5. User klik hapus pada mini card Prabowo.
6. Ticket DELETE /users/prabowo bergerak ke API Service.
7. Card Prabowo yang dibuat di Act 3 ditarik ke archive tray; slot kosong; response 204 kembali.
8. Closing memperlihatkan Adib Professional dan Jokowo Professional; Prabowo sudah tidak ada.

## 7. Asset Plan: icons.json yang Lebih Hidup

### Prinsip gaya

- Flat/semi-flat vector yang lebih manusiawi, bukan kotak label.
- Kepala, rambut, bahu, seragam, dan jas memiliki bentuk organik yang jelas.
- Pose frontal atau three-quarter ringan, ekspresi netral/ramah.
- Transparan, bukan foto, bukan likeness tokoh publik.
- Terbaca pada ukuran 64–140 px.
- Empat warna aksen maksimum dalam satu frame: mint #2CD1A8, sky #38BDF8, violet #A78BFA, amber #FBBF24. Navy/putih/abu hanya neutral.
